# UX Polish Audit — Недоработки и нереализованные мелочи

**Дата:** 2026-02-11  
**Scope:** Полный путь пользователя — от создания аккаунта до заморозки комплекса  
**Цель:** Найти не баги, а недоработки, отсутствующие мелочи, незавершённые элементы UI/функционала

---

## Методология

Аудит проведён по этапам пути пользователя:
1. Главная страница + учётные записи
2. Редактор заданий
3. Редактор комплексов
4. Прохождение комплекса (сессия S1)
5. Результаты итерации (S2) и финальные результаты (S3)
6. Календарь
7. Статистика
8. Сквозные проблемы (навигация, консистентность, обратная связь)

Каждый finding имеет **приоритет** и **категорию**:
- **[HIGH]** — заметно влияет на удобство, пользователь сталкивается часто
- **[MED]** — улучшит опыт, но не критично
- **[LOW]** — косметика / nice-to-have

Категории: `UX-FLOW` (путь пользователя), `UI-POLISH` (визуал), `MISSING-FEAT` (отсутствующий функционал), `FEEDBACK` (обратная связь пользователю), `NAV` (навигация)

## Этап 1: Главная страница + Учётные записи

### UX-1 [HIGH] [UX-FLOW] Кнопка «Настройки» (⚙️) открывает заглушку «Раздел в разработке»
**Где:** `Main.html:118` — кнопка settings открывает `devModal`  
**Проблема:** Пользователь нажимает на шестерёнку ожидая настройки (тема, язык, etc.), а видит заглушку. Это разочаровывает.  
**Решение:** Либо убрать кнопку настроек до реализации, либо сделать минимальный экран настроек (переключение темы уже работает через ThemeSwitcherUI — можно вынести в модал настроек).

### UX-2 [MED] [FEEDBACK] Нет визуального подтверждения смены профиля
**Где:** `MainLogic.js:201-204` — после selectProfile просто `window.location.reload()`  
**Проблема:** Перезагрузка всей страницы — грубый способ. Пользователь видит мигание. Нет toast "Профиль переключён на X".  
**Решение:** Показать toast перед reload или перейти на SPA-обновление без полной перезагрузки.

### UX-3 [MED] [UI-POLISH] Ссылка «Редактор заданий» в хедере скрыта на мобильных
**Где:** `Main.html:105-109` — `hidden md:flex`  
**Проблема:** На мобильных устройствах пользователь не видит путь к редактору заданий из главной. Нет гамбургер-меню.  
**Решение:** Добавить мобильное меню или показать ссылку в другом виде (иконка без текста).

### UX-4 [LOW] [UI-POLISH] Quick Access — нет возможности закрепить комплекс из этого блока
**Где:** `MainLogic.js:897-913` — кнопка "открепить" есть, а "закрепить" нет  
**Проблема:** Пользователь может открепить комплекс из Quick Access, но закрепить можно только со страницы комплексов (а там тоже нет такой кнопки!). Pin-функция фактически недоступна из UI.  
**Решение:** Добавить кнопку "Закрепить" на карточках комплексов (страница /ui/complexes) и/или в Quick Access.

### UX-5 [LOW] [UI-POLISH] Дата/время в хедере показывается только на desktop
**Где:** `Main.html:112` — `hidden md:flex`  
**Проблема:** Мелочь, но на мобильных пользователь не видит дату — менее полезная информация, но это часть "учебного" настроя.

## Этап 2: Редактор заданий

### UX-6 [HIGH] [NAV] Нет обратной навигации из редактора задания к дашборду
**Где:** Редакторы (`Point_Annotation.html`, `Test Task Editor Multiple Choice.html`, etc.)  
**Проблема:** Когда пользователь открывает конкретное задание в редакторе, нет явной кнопки "Назад к списку заданий" или breadcrumb. Пользователь вынужден использовать кнопку браузера.  
**Решение:** Добавить кнопку "← Библиотека" в шапку каждого редактора задания.

### UX-7 [MED] [FEEDBACK] Нет индикатора сохранения задания
**Где:** `base_editor.js`, `autosave_manager.js`  
**Проблема:** Пользователь не видит статуса: "Сохранено", "Сохранение...", "Несохранённые изменения". Autosave работает, но нет визуального подтверждения.  
**Решение:** Добавить статус-бар/badge рядом с заголовком: "✓ Сохранено", "● Несохранённые изменения", "⟳ Сохранение...".

### UX-8 [MED] [MISSING-FEAT] Кнопка «Настройки» в сайдбаре дашборда — заглушка
**Где:** `Main_Dashboard.html:84-89` — кнопка "Настройки" без функционала  
**Проблема:** Кнопка ничего не делает. Либо убрать, либо связать с настройками редактора (размер шрифта, автосохранение интервал, etc.).  
**Решение:** Удалить до реализации или сделать модал с базовыми настройками.

### UX-9 [MED] [UX-FLOW] Нет превью/предпросмотра задания из редактора
**Где:** Весь Editor  
**Проблема:** Пользователь создаёт задание, но не может увидеть, как оно будет выглядеть при прохождении. Нужно создать комплекс, запустить его, и только тогда увидеть результат.  
**Решение:** Добавить кнопку "Предпросмотр" в каждом редакторе — открывает мини-версию TaskRenderer с текущими данными задания.

### UX-10 [LOW] [UI-POLISH] Карточки заданий не показывают дату создания
**Где:** `dashboard.js` — task cards  
**Проблема:** Сортировка "по дате изменения" работает, но на самих карточках дата не видна. Пользователю сложно ориентироваться.  
**Решение:** Показать дату последнего изменения мелким текстом на карточке.

## Этап 3: Редактор комплексов

### UX-11 [HIGH] [FEEDBACK] Нет подтверждения успешного сохранения комплекса
**Где:** `create.html` (Complexes)  
**Проблема:** После сохранения комплекса нет явного toast/notification "Комплекс сохранён". Пользователь не уверен, сохранилось ли.  
**Решение:** Показать toast "Комплекс «{name}» сохранён" + visual feedback на кнопке.

### UX-12 [MED] [UX-FLOW] После создания комплекса нет предложения сразу запустить его
**Где:** `create.html`  
**Проблема:** После сохранения нового комплекса пользователь возвращается к списку комплексов. Было бы удобнее предложить: "Комплекс создан! Запустить сейчас?"  
**Решение:** После сохранения показать модал/toast с кнопкой "Запустить" рядом с "К списку".

### UX-13 [MED] [MISSING-FEAT] Нет дублирования комплексов
**Где:** Страница комплексов `/ui/complexes`  
**Проблема:** Пользователь не может скопировать существующий комплекс и изменить его. Приходится создавать с нуля и заново выбирать все задания.  
**Решение:** Добавить кнопку "Дублировать" рядом с "Редактировать" на карточке комплекса.

### UX-14 [LOW] [UI-POLISH] На странице комплексов нет поиска/фильтрации
**Где:** `Complexes/index.html`  
**Проблема:** При большом количестве комплексов будет сложно найти нужный. Нет строки поиска, нет фильтра по статусу (Активен/Заморожен/Не начат).  
**Решение:** Добавить search bar и фильтр-чипы по статусу.

## Этап 4: Прохождение комплекса (S1)

### UX-15 [HIGH] [FEEDBACK] Нет таймера прохождения задания/сессии
**Где:** `S1/index.html` — header  
**Проблема:** Пользователь не видит, сколько времени он тратит на задание или на всю сессию. Время фиксируется в статистике, но не отображается в UI.  
**Решение:** Добавить таймер в header сессии (рядом с progress bar): "⏱ 3:45" для текущего задания или общее время сессии.

### UX-16 [HIGH] [UX-FLOW] Нет клавиатурных сочетаний для навигации
**Где:** `S1/main.js`, `session-controls.js`  
**Проблема:** Пользователь не может нажать Enter для проверки ответа или стрелку вправо для следующего задания. Всё только мышкой.  
**Решение:** Добавить keyboard shortcuts: `Enter` → Проверить ответ (или Следующее, если уже проверено), `Escape` → модал паузы.

### UX-17 [MED] [FEEDBACK] Нет анимации перехода между заданиями
**Где:** `session-controls.js:674-676` — просто `renderTask(nextTask)`  
**Проблема:** Смена задания происходит мгновенно — нет визуального перехода. Skeleton показывается, но переход резкий.  
**Решение:** Добавить fade-out → skeleton → fade-in анимацию при смене задания.

### UX-18 [MED] [UI-POLISH] Progress bar не показывает номера заданий
**Где:** `S1/index.html:66-75` — progress label "Задание: –"  
**Проблема:** Лейбл "Задание: 3" не показывает "из скольки". Пользователь не знает, сколько заданий осталось.  
**Решение:** Показать "Задание: 3 из 12" и обновить progress bar соответственно.

### UX-19 [MED] [FEEDBACK] После проверки ответа — нет фокуса на результат
**Где:** `session-controls.js:577` — showEvaluationResult  
**Проблема:** Когда результат проверки появляется внизу страницы, а контент длинный (например, задание с изображением), пользователь может не заметить результат.  
**Решение:** Автоматический scroll к `#result-box` после показа результата.

### UX-20 [LOW] [UI-POLISH] Кнопка "Завершить комплекс" всегда видна
**Где:** `S1/index.html:77-80`  
**Проблема:** Кнопка "Завершить комплекс" рядом с "Проверить ответ" может быть нажата случайно. Это деструктивное действие.  
**Решение:** Скрыть или сделать менее заметной (outline вместо filled), показывать только после завершения N заданий.

## Этап 5: Результаты (S2, S3)

### UX-21 [HIGH] [FEEDBACK] На странице результатов итерации (S2) нет времени прохождения
**Где:** `S2/index.html` — результаты итерации  
**Проблема:** Показываются "Всего заданий", "Неправильных", "Успех %" — но нет времени, потраченного на итерацию. Пользователю важно знать, стал ли он быстрее.  
**Решение:** Добавить карточку "Время: X мин Y сек" к сводке итерации.

### UX-22 [MED] [UX-FLOW] На S2 нет возможности посмотреть свои ответы
**Где:** `S2/index.html` — trigger-tasks-list  
**Проблема:** Показаны "проблемные задания" (те, где ошибка), но пользователь не может увидеть, что именно он ответил и что было правильно. Только названия заданий.  
**Решение:** Сделать проблемные задания кликабельными — показать expand-секцию с "Ваш ответ" / "Правильный ответ".

### UX-23 [MED] [FEEDBACK] На S3 (финальные результаты) нет мотивационного сообщения
**Где:** `S3/index.html`  
**Проблема:** После завершения комплекса пользователь видит сухие цифры. Нет эмоционального фидбека: "Отличная работа!", "Есть над чем поработать", "Вы улучшили результат!".  
**Решение:** Добавить динамическое сообщение на основе success_rate: ≥90% → "Отлично!", 70-89% → "Хороший результат", <70% → "Не сдавайтесь!".

### UX-24 [MED] [NAV] На S3 кнопка "Закрыть" не ясно куда ведёт
**Где:** `S3/index.html:856-870`  
**Проблема:** Кнопка "Закрыть" — куда? На главную? К комплексам? К календарю? Нет явного указания.  
**Решение:** Заменить на две кнопки: "На главную" и "К комплексам" (как на S2 — "К списку комплексов").

## Этап 6: Календарь

### UX-25 [HIGH] [FEEDBACK] Нет визуального подтверждения запуска Daily Mix
**Где:** `calendar.html` — `startSession('daily_mix')`  
**Проблема:** При клике на карточку Daily Mix начинается запрос к серверу, но нет loading-индикатора. Если сервер отвечает медленно, пользователь может кликнуть повторно.  
**Решение:** Показать loading spinner на карточке и заблокировать повторные клики.

### UX-26 [MED] [UX-FLOW] Нет пустого состояния для health-блока
**Где:** `calendar.html:1191-1233`  
**Проблема:** Блок "Здоровье памяти" показывает "—" когда нет данных. Нет понятного empty state объясняющего, что это и когда появятся данные.  
**Решение:** Показать empty state: "Пройдите первый комплекс, чтобы начать отслеживать здоровье памяти".

### UX-27 [MED] [UI-POLISH] Кнопка "more_horiz" в блоке здоровья — заглушка
**Где:** `calendar.html:1175-1183`  
**Проблема:** Кнопка "⋯" в правом верхнем углу блока "Здоровье памяти" ничего не делает.  
**Решение:** Либо убрать, либо привязать к развёрнутому виду здоровья всех комплексов.

### UX-28 [LOW] [UI-POLISH] Schedule strip пуст при первом использовании
**Где:** `calendar.html:1043`  
**Проблема:** Полоса расписания пустая без объяснения. Пользователь не понимает, что это и зачем.  
**Решение:** Показать placeholder: "Расписание появится после активации первого комплекса".

## Этап 7: Статистика

### UX-29 [MED] [MISSING-FEAT] Нет фильтрации статистики по комплексу
**Где:** `statistics.html`, `statistics.js`  
**Проблема:** Статистика показывается общая. Пользователь не может посмотреть прогресс по конкретному комплексу или модулю.  
**Решение:** Добавить dropdown/chip-фильтр "Все комплексы" / конкретный комплекс.

### UX-30 [MED] [FEEDBACK] Нет пояснения для новых пользователей
**Где:** `statistics.html`  
**Проблема:** При первом входе все метрики показывают "0" или "—" без контекста. Пользователь не понимает, что такое "Серия" или "Освоено задач".  
**Решение:** Tooltip-подсказки уже есть (кнопки с `?`), но они мелкие. Для пустого состояния показать приветственный баннер: "Начните обучение, чтобы увидеть статистику".

### UX-31 [LOW] [UI-POLISH] Блок "Производительность" пуст без объяснения
**Где:** `statistics.html:204-216` — `performance-bars`  
**Проблема:** Пустой блок без empty state.  
**Решение:** Показать "Пока нет данных по типам задач".

## Этап 8: Сквозные проблемы

### UX-32 [HIGH] [NAV] Нет единой навигационной панели между разделами
**Где:** Все страницы  
**Проблема:** Каждая страница имеет свой header. Нет единого sidebar/navbar для переключения между Главная → Комплексы → Календарь → Статистика → Редактор. Пользователь всегда сначала возвращается на главную.  
**Решение:** Добавить lightweight navigation bar (или bottom nav на мобильных) с иконками: 🏠 Главная, 📚 Комплексы, 📅 Календарь, 📊 Статистика, ✏️ Редактор.

### UX-33 [HIGH] [FEEDBACK] Нет глобального offline/error состояния на всех страницах
**Где:** `ConnectionMonitor.js` подключён, но не на всех страницах одинаково работает  
**Проблема:** Если сервер падает во время работы, пользователь может потерять прогресс без предупреждения. ConnectionMonitor подключён, но его поведение на каждой странице разное.  
**Решение:** Стандартизировать ConnectionMonitor на всех страницах: показывать banner "Нет связи с сервером" + блокировать действия.

### UX-34 [MED] [UI-POLISH] Inconsistent header styles
**Где:** Main.html vs Calendar vs Statistics vs S1  
**Проблема:** Каждая страница имеет немного отличающийся дизайн header: разные padding, разные элементы, разный layout аватарки.  
**Решение:** Вынести header в shared component с одинаковым layout.

### UX-35 [MED] [MISSING-FEAT] Нет переключения темы на всех страницах
**Где:** `ThemeSwitcherUI.js` подключён, но нет UI-контрола для пользователя  
**Проблема:** ThemeSwitcherUI.js загружается, тема работает, но пользователь не видит кнопку переключения темы (light/dark). Переключение возможно только программно.  
**Решение:** Добавить toggle светлая/тёмная тема в header (иконка 🌙/☀️) или в модал настроек.

### UX-36 [MED] [UX-FLOW] Нет onboarding / tutorial для нового пользователя
**Где:** Весь flow  
**Проблема:** Новый пользователь создаёт аккаунт и видит пустую главную без понимания, что делать. Нет guided tour, нет подсказок.  
**Решение:** При первом входе показать welcome-screen: "1. Создайте задания в Редакторе → 2. Соберите их в Комплекс → 3. Проходите и учитесь!". Или tooltip-цепочку на 3-4 шага.

### UX-37 [LOW] [UI-POLISH] Profile modal дублируется на Calendar и Statistics
**Где:** `calendar.html:1261-1343`, `statistics.html:221-243`  
**Проблема:** Модал профиля скопирован 1:1 на трёх страницах. При этом на Calendar/Statistics он упрощённый (нет создания нового профиля, только выбор). Это не баг, но поддержка сложнее.  
**Решение:** Унифицировать через shared iframe/component или перенести профиль на отдельную страницу.

### UX-38 [LOW] [UI-POLISH] Двойной DOCTYPE в calendar.html
**Где:** `calendar.html:1-5` — `<!DOCTYPE html>` повторяется дважды  
**Проблема:** Косметический дефект, не влияет на рендеринг, но неаккуратно.  
**Решение:** Удалить дублирующий DOCTYPE.

### UX-39 [LOW] [UI-POLISH] Тройные пустые строки в calendar.html и S2, S3
**Где:** `calendar.html`, `S2/index.html`, `S3/index.html`  
**Проблема:** Файлы содержат тройные пустые строки между каждым блоком — артефакт генерации. Файлы раздуты в 3x.  
**Решение:** Минифицировать или нормализовать whitespace.
