# Welcome Screen — Спецификация

## Контекст

Сейчас при первом запуске приложение сразу показывает главную страницу (`Main.html`) и если пользователь не найден — открывает модалку выбора профиля поверх неё. Это плохо:
- Пользователь видит "пустой" дашборд без контекста
- Нет объяснения, что это за приложение
- Модалка — не полноценный онбординг

Нужен **полноэкранный Welcome Screen** — отдельная точка входа.

---

## Логика показа

```
Запуск приложения
    │
    ├─ GET /api/users → profiles[]
    │
    ├─ profiles.length === 0
    │     └─► Welcome Screen: режим ОНБОРДИНГ
    │           (описание проекта + создание первого профиля)
    │
    ├─ profiles.length === 1 && !has_password
    │     └─► Автоматический вход → Main.html
    │
    ├─ profiles.length === 1 && has_password
    │     └─► Welcome Screen: режим ВХОД
    │           (аватар + имя профиля + поле пароля)
    │
    └─ profiles.length > 1
          └─► Welcome Screen: режим ВЫБОР ПРОФИЛЯ
                (список профилей + кнопка "Создать новый")
```

**Важно:** Гостевой режим доступен всегда через неприметную ссылку внизу.

### Элементы

1. **Заголовок** — логотип (иконка `radiology` из Material Symbols) + название + подзаголовок
2. **Описание** — краткое описание возможностей приложения (4-5 буллетов)
3. **Форма создания профиля:**
   - Поле ввода имени (обязательное, 2-50 символов)
   - Галерея аватаров (из `/api/assets/avatars`)
   - Кнопка «Начать обучение» (primary, крупная)
4. **Гостевой вход** — мелкая ссылка внизу: «Войти как гость (без сохранения прогресса)»
5. **Футер** — версия + копирайт

### Поведение
- При нажатии «Начать обучение» → `POST /api/users` → `POST /api/users/select` → редирект на `/ui/main`
- Валидация имени: 2-50 символов, без спецсимволов `/\<>:"|?*`
- Если имя не заполнено — подсветить поле, не отправлять
- Аватар по умолчанию — первый из галереи

## Техническая реализация

### Новые файлы

| Файл | Назначение |
|---|---|
| `frontend/Welcome/welcome.html` | HTML страница Welcome Screen |
| `frontend/Welcome/welcome.js` | Логика: загрузка профилей, создание, выбор, валидация |

### Изменения в существующих файлах

| Файл | Изменение |
|---|---|
| `desktop-app/server.py` | Добавить роут `GET /ui/welcome` → serve `Welcome/welcome.html` |
| `desktop-app/server.py` | Добавить API `GET /api/users/should-welcome` → возвращает `{ show_welcome: true/false, mode: "onboarding" | "select" | "login", profiles: [...] }` |
| `desktop-app/webview_launcher.py` | Изменить стартовый URL: вместо `/ui/main` → `/ui/welcome` (или сделать `/ui/welcome` промежуточным, который сам редиректит) |
| `frontend/assets/MainLogic.js` | Убрать `openProfileModal()` из `loadCurrentUser()` при отсутствии пользователя → вместо этого редирект на `/ui/welcome` |

### API: `GET /api/users/should-welcome`

```json
// Нет профилей → онбординг
{ "ok": true, "show_welcome": true, "mode": "onboarding", "profiles": [] }

// Несколько профилей → выбор
{ "ok": true, "show_welcome": true, "mode": "select", "profiles": [
    { "user_id": "user_abc", "name": "Иван", "avatar_seed": "3.png", "has_password": false },
    { "user_id": "user_def", "name": "Мария", "avatar_seed": "7.png", "has_password": true }
]}

// Один профиль без пароля → не показывать welcome
{ "ok": true, "show_welcome": false }

// Один профиль с паролем → показать экран входа
{ "ok": true, "show_welcome": true, "mode": "login", "profiles": [
    { "user_id": "user_abc", "name": "Иван", "avatar_seed": "3.png", "has_password": true }
]}
```

### Редирект-логика (welcome.js)

```
1. GET /api/users/should-welcome
2. if (!show_welcome) → window.location = "/ui/main"
3. else → рендерить соответствующий режим (onboarding / select / login)
4. После успешного создания/выбора профиля → window.location = "/ui/main"
```

### Защита Main.html от "пустого" состояния

В `MainLogic.js` → `loadCurrentUser()`:
```js
if (!ok || !data.user) {
    // Вместо openProfileModal():
    window.location.href = '/ui/welcome';
    return;
}
```

Это гарантирует, что если пользователь каким-то образом попадёт на Main.html без профиля — его перенаправит на Welcome Screen.

## Дизайн-принципы

1. **Центрированная компоновка** — всё по центру экрана, max-width 480px
2. **Минимализм** — никаких сайдбаров, хедеров, навигации
3. **Консистентность** — те же CSS-переменные (lightB-variables.css), те же шрифты, те же компоненты (btn-primary, rounded-2xl и т.д.)
4. **Анимация** — мягкий fade-in при загрузке, плавные переходы между режимами
5. **Responsive** — работает на любой ширине (pywebview может быть разного размера)
6. **Доступность** — фокус на поле ввода, Enter для подтверждения, Tab-навигация

## UX-сценарии

### Сценарий A: Первый запуск
1. Пользователь открывает приложение
2. Видит красивый Welcome Screen с описанием
3. Вводит имя, выбирает аватар
4. Нажимает «Начать обучение»
5. Попадает на главную страницу

### Сценарий B: Повторный запуск (один профиль, без пароля)
1. Пользователь открывает приложение
2. Welcome Screen НЕ показывается
3. Сразу попадает на главную

### Сценарий C: Повторный запуск (несколько профилей)
1. Пользователь открывает приложение
2. Видит Welcome Screen с выбором профиля
3. Кликает на свой профиль
4. Попадает на главную

### Сценарий D: Профиль с паролем
1. Пользователь открывает приложение
2. Видит Welcome Screen с полем пароля
3. Вводит пароль → попадает на главную
4. Неверный пароль → тряска + сообщение

### Сценарий E: Гостевой вход
1. На любом экране Welcome есть ссылка «Войти как гость»
2. Клик → вход в гостевом режиме → главная (с ограничениями)
