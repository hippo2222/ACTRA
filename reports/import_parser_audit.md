# Аудит системы парсинга / импорта заданий

**Дата:** 2026-02-11  
**Область:** Полный цикл импорта заданий из текста и архивов на главной странице редактора

---

## Архитектура системы (обзор)

### Слои
1. **Парсеры** (`task_system/models/parsers/`) — 4 парсера: `OpenAnswerParser`, `SequenceParser`, `ClickTextParser`, `ClickWordsParser` + отдельный `TestFileParser`
2. **Бэкенд API** (`desktop-app/server.py`) — маршруты `/api/editor/import/parse`, `/api/editor/import/execute`, `/api/editor/import/check`, `/api/editor/import/confirm`, `/api/editor/test/import`, `/api/editor/test/export`, `/api/editor/export/tasks`
3. **Фронтенд** (`frontend/Editor/import_manager.js`) — 4-шаговый визард (модуль/тема → текст/архив → превью → подтверждение)
4. **ImportExportService** (`desktop-app/services/import_export_service.py`) — ZIP-архив: экспорт, валидация, атомарный импорт

### Поток данных (текст)
```
UI textarea → POST /api/editor/import/parse → 4 парсера → валидация → preview JSON
→ POST /api/editor/import/execute → _save_task_to_storage → task.json на диск
```

### Поток данных (архив)
```
UI file upload → POST /api/editor/import/check → ImportExportService.validate_import_archive
→ POST /api/editor/import/confirm → import_tasks_atomic (NDJSON streaming)
```

## КРИТИЧЕСКИЕ БАГИ (ломают работу)

### BUG-1 ★★★ `excludedTasks` не учитываются при импорте
**Файл:** `frontend/Editor/import_manager.js` → `handleImport()`  
**Суть:** Пользователь может исключить задания кнопкой "Исключить" / Bulk Exclude, но `handleImport()` (строка 878) фильтрует **только** по `status !== 'error'` и **полностью игнорирует** `this.excludedTasks`. Все исключённые задания всё равно отправляются на сервер и импортируются.

```js
// строка 878 — фильтр неполный
const validTasks = this.parsedResult.tasks.filter(t => t.status !== 'error');
// Нет .filter((t, i) => !this.excludedTasks.has(i))
```

**Влияние:** Функционал "Исключить задание" визуально работает, но фактически бесполезен.

### BUG-2 ★★★ Предупреждения парсеров привязываются к неверным заданиям
**Файл:** `desktop-app/server.py` → `import_parse()`, строки 3701–3709  
**Суть:** Цикл ищет `warning.get('index') == i`, где `i` — глобальный индекс задания в `all_tasks`. Но каждый парсер нумерует индексы **с нуля внутри своего типа**. Если текст содержит 2 `@OPEN_ANSWER` и потом 1 `@SEQUENCE`, то sequence-задание получит глобальный индекс `i=2`, а его предупреждения имеют `index=0` (первое задание этого парсера). Предупреждения не привязываются к нужным заданиям.

```python
for p_marker, p_parser in parsers:
    if p_marker in text:
        for warning in p_parser.warnings:
            if warning.get('index') == i:  # <-- i глобальный, warning['index'] локальный
```

**Влияние:** При смешанном импорте предупреждения отображаются не у тех заданий или теряются.

### BUG-3 ★★★ `ClickWordsParser` берёт только первую строку текста
**Файл:** `task_system/models/parsers/click_words_parser.py`, строки 91–93  
**Суть:** Многострочный текст задания обрезается до первой непустой строки:

```python
if text_content is None:
    text_content = line_stripped  # только первая строка
```

Если текст с ошибками занимает несколько строк — парсер берёт только первую. Индексы ошибок перестают соответствовать словам.

**Влияние:** Многострочные задания click_words парсятся некорректно.

### BUG-4 ★★ `_validate_with_task_type` конфликт `correct` vs `is_correct`
**Файл:** `desktop-app/server.py`, строка 3335–3337  
**Суть:** Парсер `ClickTextParser` создаёт опции с ключом `correct`, а `_validate_with_task_type` считает правильные по ключу `is_correct`:

```python
correct_count = sum(1 for opt in options if bool(opt.get("is_correct")))
# Парсер даёт: {"text": "...", "correct": True}  ← is_correct нет!
```

`_normalize_click_import_data` конвертирует `correct → is_correct`, но вызывается **после** валидации: валидатор не находит правильных ответов → ошибка "Должен быть ровно один правильный вариант" при полностью корректном вводе.

**Дополнительно:** Валидатор требует **ровно 1** правильный ответ (`correct_count != 1`), а формат `ClickTextParser` позволяет несколько `+`. Это противоречие.

### BUG-5 ★★ `_save_task_to_storage` — ключи уровней последовательности
**Файл:** `desktop-app/server.py`, строки 3493–3494  
**Суть:** `sorted(levels.keys())` оперирует на dict-ключах, которые приходят из парсера как `int` (строка 100 `sequence_parser.py`: `level_num = int(...)`), но после JSON-сериализации/десериализации через API они становятся **строками**. `sorted()` для строк даст `"1" < "10" < "2"`, ломая порядок уровней при ≥10 уровнях.

## ОШИБКИ СРЕДНЕГО ПРИОРИТЕТА

### BUG-6 ★★ Парсеры не сбрасывают `errors` / `warnings` между вызовами
**Файл:** `task_system/models/task_import_parser.py`  
**Суть:** `self.errors = []` и `self.warnings = []` задаются в `__init__`, но если парсер переиспользуется (хотя сейчас в `import_parse()` создаются новые экземпляры), ошибки накапливаются. Потенциально опасно при рефакторинге.

### BUG-7 ★★ Archive import: файл загружается дважды
**Файл:** `frontend/Editor/import_manager.js`, строки 804–811 (check) и 891–895 (confirm)  
**Суть:** При архивном импорте файл отправляется на сервер **дважды**: сначала для `/api/editor/import/check`, затем тот же файл повторно для `/api/editor/import/confirm`. Для архивов в 200MB — это неоправданный overhead. Сервер не кэширует первый загруженный файл.

### BUG-8 ★★ `import_check` удаляет temp-файл до того, как `import_confirm` его использует
**Файл:** `desktop-app/server.py`, строки 1155–1160  
**Суть:** `finally` блок в `import_check` удаляет загруженный temp-файл. Но пользователь позже вызывает `import_confirm`, которому нужен тот же архив. Из-за этого `import_confirm` требует повторной загрузки файла. Логика работает, но неэффективно (см. BUG-7).

### BUG-9 ★★ `_save_task_to_storage` использует `_headless_app_ctx.data_dir`, а не `storage_service`
**Файл:** `desktop-app/server.py`, строка 3824  
**Суть:** Путь к данным берётся из `_headless_app_ctx.data_dir`, а не из `storage_service.modules_dir`. Если пути рассинхронизированы (конфигурация), задание сохранится не туда, и `storage_service.reload_modules()` его не увидит.

### BUG-10 ★★ Step 4 показывает `selectedModule` как string-ID, а не человеческое имя
**Файл:** `frontend/Editor/import_manager.js`, строка 397  
**Суть:** `this.selectedModule?.name || this.selectedModule` — но `selectedModule` всегда строка (значение `<select>`), а не объект. Поле `name` никогда не существует, поэтому пользователь видит техническое ID типа `module_01`, а не "Рентгенология грудной клетки".

### BUG-11 ★ `showTaskDetails` использует `alert()` 
**Файл:** `frontend/Editor/import_manager.js`, строки 632–646  
**Суть:** Детали задания показываются через `alert()`, которое не поддерживает форматирование, переносы строк некорректно отображаются в некоторых браузерах, и блокирует UI. Также помечено комментарием "Simple alert for now - can be enhanced to show modal".

### BUG-12 ★ Drag & drop для архива не реализован
**Файл:** `frontend/Editor/import_manager.js`  
**Суть:** Drop-zone с `id="import-drop-zone"` визуально выглядит как area для drag-and-drop (текст "Перетащите файл сюда"), но нет `dragover`/`drop` обработчиков. Работает только клик на скрытый `<input type="file">`.

### BUG-13 ★ `_generate_unique_task_id` вызывает `get_tasks` в цикле
**Файл:** `desktop-app/server.py`, строки 3427–3435  
**Суть:** Для каждого нового ID загружается полный список заданий темы. При импорте 50 заданий это 50 вызовов `get_tasks`, создавая O(n²) нагрузку. При UUID-коллизии (практически невозможна) — бесконечный цикл.

## НЕРЕАЛИЗОВАННЫЕ АСПЕКТЫ

### MISSING-1 ★★★ Нет парсера для типа `test` (тестовые вопросы)
**Суть:** Тип задания `test` имеет свой `TestFileParser` (`task_system/models/test_parser.py`), но он **не интегрирован** в систему маркерного импорта из текста на главной странице. У `TestFileParser` свой формат (`?вопрос` / `+/-ответ`), отдельный API-маршрут (`/api/editor/test/import`), и он доступен только из редактора тестов, а не из общего визарда импорта.

**Предложение:** Добавить маркер `@TEST` и адаптер `TestImportParser` в систему parsers, либо позволить в Step 1 загрузить `.txt` файл в формате `TestFileParser` наряду с маркерным форматом.

### MISSING-2 ★★★ Нет парсера для типа `draw` (рисование)
**Суть:** Тип `draw` присутствует в системе и может быть создан через Create Task Modal, но не имеет ни парсера, ни поддержки в импорте. Не указан в подсказке форматов.

**Предложение:** Для draw-заданий основной контент — изображение + аннотации. Текстовый парсинг здесь ограничен, но для архивного импорта draw-задания должны полноценно поддерживаться.

### MISSING-3 ★★★ Формат `@CLICK_WORDS` неудобен — нет поддержки маркировки ошибочных слов inline
**Суть:** Сейчас ошибочные слова задаются числовыми индексами: `индексы: 2, 5`. Пользователь должен вручную считать номера слов. Это крайне неудобно для текстов > 10 слов.

**Предложение:** Добавить альтернативный синтаксис — `**слово**` или `[слово]` для обозначения ошибочных слов прямо в тексте. Парсер автоматически вычислит индексы.

### MISSING-4 ★★ Нет возможности редактировать задание на этапе превью
**Суть:** Step 3 показывает карточки с превью, кнопки "Детали" (alert) и "Исключить". Нет inline-редактирования. Если пользователь заметил опечатку — нужно вернуться на Step 2, исправить текст, повторить парсинг.

**Предложение:** Разрешить inline-редактирование имени задания, промпта, и ключевых полей на Step 3.

### MISSING-5 ★★ Нет истории / лога импортов
**Суть:** После успешного импорта нет записи: когда, откуда, сколько заданий было импортировано. Поле `meta.imported: true` ставится, но дата/источник не фиксируются.

**Предложение:** Записывать `meta.import_date`, `meta.import_source` (text / archive / filename).

### MISSING-6 ★★ Нет экспорта для заданий, импортированных через текст
**Суть:** `/api/editor/export/tasks` работает только для ZIP (через `ImportExportService`). Нет обратного экспорта в текстовый формат маркеров (`@OPEN_ANSWER`, `@SEQUENCE` и т.д.).

**Предложение:** Добавить `export_to_text()` методы в парсеры (обратная сериализация). Это позволит копировать задания между проектами через буфер обмена.

### MISSING-7 ★ Нет поддержки вложенных маркеров / комментариев в формате
**Суть:** Формат поддерживает `//` как комментарий, но не поддерживает:
- Метаданные задания (сложность, теги)
- Настройки (`max_length`, `time_limit`, `case_sensitive`)
- Ссылки на изображения в текстовом формате

### MISSING-8 ★ Нет preview / syntax highlighting в textarea
**Суть:** Step 2 — обычный `<textarea>` без подсветки синтаксиса маркеров. При вводе большого текста сложно отличить `@OPEN_ANSWER`, `#`, `+`, `-` визуально.

### MISSING-9 ★ Нет счётчика распознанных заданий в реальном времени
**Суть:** Пользователь видит результат парсинга только после нажатия "Далее". Нет live-preview количества распознанных маркеров по мере набора текста.

### MISSING-10 ★ `sanitize_text` слишком агрессивен
**Суть:** `re.sub(r'<[^>]+>', '', text)` удаляет всё похожее на HTML-теги. Если текст задания содержит медицинские обозначения вроде `<3 мм` или математические `a<b`, они будут повреждены.

## СЛАБЫЕ МЕСТА / QUALITY ISSUES

### WEAK-1 ★★ Нет атомарности для text-импорта
**Суть:** `import_execute()` сохраняет задания одно за другим. Если третье из пяти падает — первые два уже сохранены, нет rollback. Для ZIP-импорта есть аналогичная проблема (отмечено в тестах: "per-task atomic, not batch atomic").

### WEAK-2 ★★ Validation logic дублируется между парсерами и server.py
**Суть:** Парсеры имеют `_validate_single_task()`, а server.py имеет `_validate_with_task_type()` — оба проверяют одно и то же с разными правилами и разными пороговыми значениями. Нет единого источника правды для правил валидации.

### WEAK-3 ★ Step stepper не кликабелен
**Суть:** Шаги 1-4 визуально выглядят как кликабельные кружки, но `goToStep()` не привязан к ним через onclick. Пользователь не может перепрыгнуть на предыдущий шаг кликом по кружку.

### WEAK-4 ★ `closeImportModal` не сбрасывает `importMode` и `uploadedFile`
**Файл:** `frontend/Editor/dashboard.js`, строки 1583–1590  
**Суть:** При закрытии модала сбрасывается `selectedModule`, `selectedTopic`, `sourceText`, `parsedResult`, `excludedTasks`, но **не** `importMode`, `uploadedFile`, `selectedTasks`, `checkResult`. При повторном открытии могут остаться артефакты предыдущего сеанса.

### WEAK-5 ★ `import_tasks_atomic` — имя вводит в заблуждение
**Файл:** `desktop-app/services/import_export_service.py`  
**Суть:** Функция называется `atomic`, но фактически не является таковой — каждое задание обрабатывается отдельно, без транзакции или rollback. Имя обещает больше, чем код делает.

### WEAK-6 ★ `_check_task_dependencies` ловит `.json` как "image"
**Файл:** `desktop-app/services/import_export_service.py`, строка 296  
**Суть:** `ALLOWED_EXTENSIONS = {'.json', '.jpg', ...}`. `scan_for_images` проверяет любое строковое значение, заканчивающееся на расширение из `ALLOWED_EXTENSIONS`, включая `.json`. Если поле содержит строку `"config.json"`, она будет проверена как зависимость-картинка.

## ПРЕДЛОЖЕНИЯ ПО УЛУЧШЕНИЮ

### IMPROVE-1: Unified Parser Registry
Заменить хардкод списка парсеров в `server.py` на реестр с автоматическим обнаружением:
```python
PARSER_REGISTRY = {
    '@OPEN_ANSWER': OpenAnswerParser,
    '@SEQUENCE': SequenceParser,
    '@CLICK_TEXT': ClickTextParser,
    '@CLICK_WORDS': ClickWordsParser,
    '@TEST': TestQuestionsParser,  # новый
}
```

### IMPROVE-2: Inline маркировка ошибок для CLICK_WORDS
Новый альтернативный формат:
```
@CLICK_WORDS
# Найдите ошибки в тексте
Это правильный [ашибка] текст с [нипрвильным] написанием
```
Парсер автоматически вычисляет индексы из `[...]` обёрток.

### IMPROVE-3: Live preview в textarea
Добавить debounced подсчёт маркеров при вводе текста, показывая badge рядом с кнопкой "Далее": "Найдено: 3 open_answer, 2 sequence".

### IMPROVE-4: Modal вместо alert для деталей задания
Заменить `alert()` в `showTaskDetails()` на полноценный modal с форматированием, подсветкой полей, и возможностью inline-редактирования.

### IMPROVE-5: Сохранение temp-файла архива между check и confirm
Сохранять загруженный архив на сервере с TTL (например, 10 мин), возвращать `archive_id` в ответе `/check`, использовать его в `/confirm` вместо повторной загрузки.

### IMPROVE-6: Поддержка метаданных в текстовом формате
```
@OPEN_ANSWER
# Вопрос
@ difficulty: 3
@ tags: рентген, грудная клетка
@ max_length: 500
= Эталонный ответ
* ключевое слово
```

### IMPROVE-7: Batch ID generation
Заменить цикл `_generate_unique_task_id` на single-batch генерацию: загрузить список существующих ID один раз, сгенерировать N уникальных UUID за раз.

## РЕЗЮМЕ

- **Критических багов:** 5 (BUG-1 через BUG-5)
- **Средних багов:** 8 (BUG-6 через BUG-13)
- **Нереализованных аспектов:** 10 (MISSING-1 через MISSING-10)  
- **Слабых мест:** 6 (WEAK-1 через WEAK-6)
- **Предложений:** 7 (IMPROVE-1 через IMPROVE-7)

Система имеет хорошую архитектурную основу (базовый класс парсера, 4-шаговый визард, streaming для больших архивов), но содержит ряд функциональных багов, которые делают часть UI бесполезной (excluded tasks, warnings mapping), и заметные пробелы (test/draw parsers, inline editing).
