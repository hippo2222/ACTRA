# Onboarding Tour And Reference Plan

## Summary

План описывает общий механизм обучающих подсветок ACTRA: first-visit обучение для экранов продукта и переиспользование тех же материалов в будущем экране "Справочник".

Существующий прототип механизма найден в редакторе тестовых заданий при вставке изображения из буфера:

- `frontend/Editor/test_editor.js`: `syncActiveImagePasteTargetUI`, `setPasteImageTargetMode`, `openPasteImageTargetModal`, обработчики выбора цели вставки.
- `frontend/Editor/test_editor.css`: `body.paste-image-selection-mode`, `is-paste-selectable`, `is-paste-target`, затемнение фона и поднятие нужных областей поверх оверлея.
- `frontend/Editor/Test Task Editor Multiple Choice.html`: `#paste-image-target-modal`.

Текущий механизм локальный для тестового редактора. Для обучения его стоит вынести в общий слой: оверлей, подсветка целевых элементов, текстовые облачка, пошаговая навигация, сохранение факта прохождения.

## Core Implementation

- Добавить общий модуль `frontend/assets/OnboardingTour.js` и стили `frontend/assets/onboarding-tour.css`.
- Добавить каталог сценариев `frontend/assets/onboarding_tours.js`.
- Структура сценария:
  - `tourId`
  - `version`
  - `route`
  - `title`
  - `summary`
  - `steps`
- Структура шага:
  - `target`: CSS selector целевой области.
  - `title`: короткий заголовок облачка.
  - `body`: объяснение смысла элемента.
  - `placement`: предпочтительная позиция облачка.
  - `fallback`: поведение, если элемент не найден или скрыт.
  - `referenceCategory`: раздел будущего справочника.
- Хранить факт прохождения в существующем `/api/ui/settings`:
  - `settings.onboarding.seen[tourId] = version`
  - `settings.onboarding.disabled = true` для полного отключения.
  - При ошибке API использовать `localStorage` как временный fallback.
- Добавить экран `/reference` или `/reference.html`, который использует те же данные туров как справочник.
- Обновить `frontend/assets/GlobalHeader.js`: кнопка "Справочник" должна открывать новый экран, а не показывать заглушку.

## Visual Design Requirements

- Облачки с обучающим текстом должны быть визуально приятными и аккуратно встроенными в стиль ACTRA, а не выглядеть как системные браузерные tooltip.
- У каждого облачка должна быть заметная стрелка-указатель на подсвеченный элемент. Стрелка должна адаптироваться к `placement` и не теряться на светлой или тёмной теме.
- Цвета, тени, бордеры, фон, текст и акценты должны использовать существующие семантические переменные проекта: `--color-surface-*`, `--color-text-*`, `--color-primary-*`, `--color-border-*`, `--color-bg-*`, `--shadow-*` и близкие локальные токены.
- Обязательна поддержка всех цветовых схем через `ThemeManager`: не хардкодить палитру под одну тему, проверять контраст и читаемость в светлых/тёмных вариантах.
- Визуальный стиль должен быть спокойным и продуктовым: выразительная подсветка цели, мягкое затемнение фона, читаемая типографика, без декоративного шума и без конфликтов с существующими модальными окнами.
- Для мобильных экранов облачко должно занимать безопасную ширину, не перекрывать критичные действия и корректно переносить длинный текст.

## Task Editor Training Decision

- На странице дашборда редактора заданий должен быть основной first-visit tour: он объясняет структуру "модуль -> тема -> задание", поиск, сортировку, создание задания, импорт, AI-анализ и переход к рабочему редактору.
- Для конкретных типов заданий не запускаем полноценное обучение автоматически при каждом первом открытии типа, создании нового задания или редактировании сохраненного задания. Это слишком часто прерывает рабочий сценарий пользователя.
- У каждого конкретного редактора задания должен быть доступный ручной запуск обучения: кнопка помощи/обучения в верхней панели редактора и карточка в будущем справочнике.
- В конце тура дашборда редактора нужно явно сообщить, что механика конкретных типов заданий находится в справочнике и может быть открыта из самого редактора типа.
- Допустим мягкий первый сигнал для сложных типов: короткое предложение "Открыть обучение по этому типу?" без принудительного запуска тура.
- Сценарии создания и редактирования сохраненного задания используют один и тот же type-specific материал, потому что различается контекст открытия, а не основная механика редактора.

## Page Rollout Order

1. **Главная (`/main`)**
   - Подсветить верхнюю навигацию, быстрый доступ, карточки "Каталог / Комплексы", блок календаря и статистики.
   - Смысл: где продолжить обучение, где искать материалы, где создавать, где видеть ритм и прогресс.

2. **Комплексы (`/complexes`)**
   - Подсветить поиск, фильтры, карточку комплекса, действия запуска/продолжения, создание/импорт/код доступа.
   - Смысл: комплекс как основной сценарий обучения; фильтры помогают найти активные, повторение и сохранённые из каталога.

3. **Прохождение комплекса (`/session/...`, S1)**
   - Показывать только до первого ответа.
   - Подсветить прогресс и сложность, тело задания, кнопку проверки, блок результата/разбора.
   - Смысл: как отвечать, как читать обратную связь, когда переходить дальше, что значит пауза.

4. **Итоги итерации и финальные итоги (S2/S3)**
   - S2: процент успеха, ошибки, рекомендация продолжения, разбор.
   - S3: общий результат, что закрепилось, куда перейти после завершения.
   - Смысл: итоги не просто оценка, а навигация к следующему учебному действию.

5. **Календарь (`/calendar`)**
   - Подсветить дневной микс, фокус дня, лимит времени, ленту ближайших дней, здоровье памяти.
   - Смысл: календарь отвечает "что учить сегодня" и "где начинает проседать память".

6. **Статистика (`/statistics`)**
   - Подсветить общие метрики, динамику времени, связи теории и комплексов, статистику по типам задач.
   - Смысл: объяснить, какие метрики влияют на дальнейшее обучение, без перегруза цифрами.

7. **Микрокарточки (`/microcards`)**
   - Два тура: список колод и режим повторения.
   - Список: due/new/today, поиск, фильтры, карточка колоды.
   - Повторение: лицевая сторона, раскрытие, оценки Again/Hard/Good/Easy.
   - Смысл: короткое повторение отдельно от больших комплексов.

8. **Каталог (`/catalog`)**
   - Подсветить поиск, фильтры "Комплексы / Теории / Сохранённые", карточки публикаций, панель деталей.
   - Смысл: как найти материал, сохранить в библиотеку, открыть теорию или комплекс.

9. **Теория / Центр теории (`/theory-center`)**
   - Подсветить список теорий, связи с комплексами, просмотр материала, создание/редактирование.
   - Смысл: теория как контекст для комплексов, а не отдельная папка документов.

10. **Редактор теории**
    - Подсветить библиотеку теорий, заголовок, редактор контента, панель форматирования/изображений, сохранение/публикацию.
    - Смысл: как создать материал, который потом связывается с темами и комплексами.

11. **Редактор (`/editor`)**
    - Подсветить дерево модулей/тем, сетку заданий, поиск/сортировку, создание задания, импорт/AI-инструменты.
    - Смысл: структура "модуль -> тема -> задание" и быстрый путь к созданию материалов.
    - Это основной first-visit tour для раздела создания заданий.

12. **Конструктор комплекса (`/complexes/create`)**
    - Подсветить название/описание, теорию комплекса, выбранные задания, цепочки, правую библиотеку заданий, готовность/публикацию/сохранение.
    - Смысл: комплекс как сценарий прохождения, а не просто список задач.

13. **Конкретные редакторы заданий**
    - Начать с редактора тестового задания, потому что там уже есть похожий механизм.
    - Подсветить список вопросов, текст вопроса, варианты ответов, изображения вопроса/варианта, банк изображений, импорт/экспорт, сохранение.
    - Смысл: как собрать задание, как добавить картинки, где переиспользовать изображения.
    - Эти туры не запускаются принудительно при создании или редактировании задания; пользователь открывает их из справочника или кнопки помощи в конкретном редакторе.

14. **Настройки (`/settings`)**
   - Подсветить профиль, оформление, AI keys, безопасность.
   - Смысл: где менять личные параметры и подключать возможности, не мешая основному обучению.

## Editor Dashboard Tour Plan

Proposed tour id: `editor-dashboard-authoring`.

Total states: 5.

1. **Структура редактора**
   - Targets: sidebar shell, module/topic tree, active module/topic item.
   - Explain: редактор заданий организован как "модуль -> тема -> задание"; выбор темы меняет содержимое рабочей области.
   - Expected callouts: "Модули и темы", "Текущий раздел".

2. **Инструменты автора**
   - Targets: "Новый модуль", "Импорт заданий", "Анализ теории", "Черновики", "Центр теории".
   - Explain: где создавать структуру, где импортировать материалы, где запускать AI-анализ теории, где восстанавливать черновики и где работать с теорией.
   - Keep the state compact: group related sidebar actions into 2-3 callouts, not one callout per button.

3. **Поиск и порядок**
   - Targets: breadcrumbs, search input, sort control.
   - Explain: хлебные крошки показывают текущий контекст, поиск находит задания/модули/файлы, сортировка помогает быстро разобрать список.
   - This state should not open the sort dropdown automatically unless the placement is stable on desktop and mobile.

4. **Рабочая область заданий**
   - Targets: task grid, existing task card, "Новое задание" card.
   - Explain: карточки открывают сохраненные задания для редактирования; новая карточка запускает создание задания в выбранной теме.
   - Demo data should include at least one saved task card so the tour can explain both edit and create flows.

5. **Создание задания и переход к типам**
   - Targets: create task modal, module/topic selectors, task name, task type selector, submit button.
   - Explain: при создании пользователь выбирает контекст, название и тип; после создания откроется конкретный рабочий редактор.
   - Final message: обучение по конкретным типам заданий не запускается принудительно; его можно открыть из справочника или кнопки помощи внутри редактора типа.
   - This state may be interactive: the tour can open the create-task modal from the "Новое задание" card, then close it when the tour exits or moves back.

Implementation notes:

- Add `data-onboarding-target` attributes to stable containers instead of targeting utility classes.
- Suggested targets: `editor-dashboard-sidebar`, `editor-sidebar-actions`, `editor-module-tree`, `editor-workspace-toolbar`, `editor-breadcrumbs`, `editor-search`, `editor-sort`, `editor-task-grid`, `editor-create-task-card`, `editor-create-task-modal`, `editor-create-task-context`, `editor-create-task-type`, `editor-create-task-submit`.
- Use a demo/dashboard preview state for first-visit and reference playback so the tour does not depend on a user's real modules or empty library.
- Do not include full type-specific tutorials in this dashboard tour. Link to the reference/type help entry from the final state.

## Reference Screen

- Экран "Справочник" должен использовать те же данные, что и first-visit обучение.
- Базовые разделы:
  - Начало работы
  - Обучение и комплексы
  - Повторение и календарь
  - Статистика
  - Каталог и библиотека
  - Создание материалов
  - Настройки
- Для каждого тура показывать:
  - краткое назначение экрана;
  - список шагов с теми же заголовками и объяснениями;
  - кнопку "Показать на экране", если пользователь находится на совместимом маршруте или можно перейти на него.

## Test Plan

- Unit/Vitest:
  - выбор тура по route;
  - сохранение `seen`;
  - fallback при отсутствующем target;
  - повторный запуск из справочника;
  - отключение всех подсказок.
- Browser smoke:
  - первый визит показывает тур;
  - закрытие записывает состояние;
  - повторный визит не показывает тур;
  - "Справочник" открывает тот же контент.
- Visual checks:
  - desktop/mobile;
  - целевой элемент видим во viewport;
  - облачко не перекрывает целевую область критично;
  - Escape закрывает тур;
  - Tab не уводит фокус под оверлей.
- Regression:
  - существующая вставка изображения в тестовом редакторе продолжает работать без изменения поведения.

## Assumptions

- First-visit обучение включено по умолчанию для всех пользователей.
- Первое посещение считается отдельно по `tourId + version`, чтобы после обновления текста можно было показать новый тур.
- Пользователь может закрыть отдельный тур или отключить все подсказки в настройках.
- "Справочник" использует те же данные туров, поэтому обучающий контент пишется один раз и переиспользуется в двух местах.
