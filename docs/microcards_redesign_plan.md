# Microcards: план редизайна по итогам аудита (2026-06-10)

Статус: согласован с владельцем продукта. Источник: полный аудит режима против
исходной парадигмы («Quizlet-аналог: карточки + заучивание, шаринг как у
комплексов, геймификация, дофаминовый UX»).

Контекст кода: сервер `desktop-app/services/microcards_service_v2.py` +
`desktop-app/routes/microcards_routes_v2.py`, фронтенд
`frontend/Microcards/microcards.{js,html}`. V2 — канон; V1-стек подлежит выпилу
(фаза 5). Уже реализовано до этого плана: мастери-цикл с замешиванием ошибок,
first-try-звёзды, покарточный L1-гейт, прозрачный HUD, фикс анимации очков.

## Зафиксированные продуктовые решения

- L1 остаётся самооценкой («знаю/не знаю») — обманывающий обманывает себя;
  очки/звёзды приватны.
- Серебряные звёзды = уровень 1, золотые = уровень 2.
- Три режима входа в колоду: **Просмотр** (листание без оценивания),
  **Повторение** (SRS, очки+комбо, БЕЗ звёзд и рекордов), **Прохождение**
  (вся колода на одном уровне, мастери-цикл, звёзды и рекорды только за
  завершённый прогон).
- Звёзды колоды = лучший завершённый прогон. Гейт L2 = завершён хотя бы один
  L1-прогон. Legacy-рекорды (сессионная модель) — обнуляются.
- В Повторении форма проверки адаптивна per-card: слабые/новые — L1-форма,
  окрепшие (`consecutive_correct`/`level`) — форма с вводом (даёт больше
  очков), но только после разблокировки L2 колоды. Микро-анимация «карточка
  окрепла» при первом повышении формы.
- Прогон многоподходный: пауза = чекпойнт; «выйти без сохранения» = откат к
  последнему чекпойнту (теряется только текущий подход); полный сброс прогона —
  отдельная явная кнопка с подтверждением.
- Размер сессии не выносится числом: Повторение — пресеты «Дневная нагрузка»
  (Лайт 10 / Стандарт 20 / Интенсив 40), Прохождение — вся колода.
- Реверс — per-deck настройка (Прямо / Реверс / Смешанно; смешанно — только
  L1/Просмотр), кнопка на странице колоды. Бэкенд уже поддерживает.
- Звуки — CC0-сэмплы файлами (синтез остаётся как fallback), модалка настроек
  на главной: звук вкл/громкость, анимации (+ prefers-reduced-motion),
  дневная нагрузка, дневная цель.
- Дневная цель (N повторений/день, кольцо на главной) — включена. Бейджи и
  «уровень пользователя» — вне плана.
- Стрик — единый, серверный (из review-событий); localStorage-стрик выпилить.
- Импорт: apkg (legacy-формат, только текст, cloze → карточки с пропуском,
  медиа пропускаем) и docx (извлечение текста → существующий авто-парсер).
  PDF — нет. AI — остаёмся на промпт-хелпере. Свои файлы картинок — нет.
- Bulk-операции в редакторе: мультивыбор + массовое удаление с undo (паттерн
  из дашборда редактора заданий). Перенос карточек между колодами — нет.
- Гость не имеет доступа ни к чему (как сейчас).

## Фаза 0 — целостность данных (первый приоритет) — ✅ ВЫПОЛНЕНА 2026-06-10

0.1 **Баг: редактирование колоды при активной сессии.**
  - Сервер: в `delete_card` вычищать id из очередей активных сессий владельца
    этой колоды (+пересчёт unique_total/mastered/pending_retry, сдвиг cursor).
  - Auto-heal в `submit_answer`: `card_not_found` для карточки из очереди →
    удалить все её вхождения из очереди, пересчитать счётчики, вернуть сессию
    (не 404 всей сессии).
  - Фронт: при resume карточки уже перезагружаются; добавить guard на
    несовпадение (карточка очереди отсутствует в state.cards → re-sync).

0.2 **Реконсиляция прогресса linked-колод (важнейшая проблема аудита).**
  - В `_resolve_linked_deck` при `resolved_ids != current_ids`: миграция
    review-states ТЕКУЩЕГО пользователя по контент-хэшу (нормализованные
    front+back): старый state (stability/difficulty/level/l1_mastered)
    переносится на новый card id. Несматченные — честный сброс.
  - Проверить/закрепить тестом: дедуп при реимпорте автора сохраняет card id
    при неизменном содержимом.

0.3 **Аудит комплексов на ту же болезнь.** РЕЗУЛЬТАТ: комплексы безопасны.
  Lineage-ключ (`services/workspace_lineage.py`) включает
  `source_catalog_version_id` на ВСЕХ уровнях (complex/module/topic/task/
  theory): реимпорт той же версии → reuse существующей копии без мутаций;
  импорт НОВОЙ версии → lineage не матчится → создаётся полностью новая
  копия с новыми id, старая копия и прогресс (`module/topic/task`-ключи)
  не затрагиваются. Гарантия закреплена тестом-растяжкой
  `tests/unit/test_workspace_lineage_version_pinning.py`.
  Trade-off (не баг, кандидат в бэклог UX): при импорте новой версии у
  пользователя копятся дубликаты копий; механики «обновить мою копию на
  новую версию с переносом прогресса» не существует.

## Фаза 1 — ядро: три режима и новая экономика — ✅ ВЫПОЛНЕНА 2026-06-10

Реализация: сессии получили `mode` (run/review) и слоты активности
`active_by_deck = {review, run_l1, run_l2}` (легаси-указатели сбрасываются);
прогон = вся колода, finish-эндпоинт считает звёзды серверно и пишет рекорд
(schema 2.0, legacy обнулён при первом чтении); гейт L2 = `l1_run_completed`;
чекпойнт при паузе + `/abandon` (откат подхода); review отдаёт `composition`
и `card_forms` (ввод для окрепших карточек при открытом гейте, премия очков
×2, «карточка окрепла»); фронт: startRun/startReview/startBrowse, деталка с
карточками прогонов («Прогон: X/N · Продолжить/Сбросить»), Просмотр-вью,
диалог выхода по режиму. Замечание: события FSRS, записанные в откатанном
подходе, не удаляются (повторение физически состоялось) — осознанно.

1.1 **Сущность «прогон» (run), сервер.**
  - `start_run(deck_id, level)`: очередь = вся колода, мастери-цикл (уже
    реализован), level фиксирован на прогон.
  - Чекпойнты: пауза пишет snapshot (queue/cursor/stats/xp/combo);
    «выйти без сохранения» восстанавливает последний чекпойнт; «сбросить
    прогон» — явное удаление.
  - Гейт L2: `l2_unlocked = существует завершённый L1-прогон колоды`
    (замена покарточного агрегата; `l1_mastered` остаётся как метрика).
    При добавлении карточек в колоду гейт НЕ закрывается задним числом
    (прогон был честно завершён), но новая звёздная попытка идёт по полной
    колоде.
  - Рекорды: только за завершённый прогон; хранить score, stars, level,
    deck_size на момент прогона. Legacy-рекорды обнулить (миграция).
  - SRS: ответы прогона дают те же FSRS-события (одно на карточку за прогон).

1.2 **Повторение (SRS-режим).**
  - Подпись состава перед стартом: «К повторению: X · Новых: Y» (убираем
    «магию»).
  - Очки+комбо есть, рекордов/звёзд нет.
  - Адаптивная форма per-card: L1-форма по умолчанию; форма с вводом для
    карточек с `level == 2` (или `consecutive_correct >= 3`) И разблокированным
    L2 колоды; премия очков за ввод; чип формы на карточке; анимация
    «карточка окрепла» при первом повышении.

1.3 **Очки.**
  - База: L1 = 100, L2 (ввод) = 200. Комбо-множители без изменений.
  - Пересдача в мастери-цикле = половина базы уровня (50/100), без множителя.
  - Максимум считается от размера колоды (прогон) / состава сессии
    (повторение). Рекорд показывается с размером: «2840/3600 · 24 карточки».

1.4 **Просмотр.** Листание с флипом/свайпом, подсказки, картинки, без
  оценивания и без записи (ни FSRS, ни статистики). Кнопка на деталке.

1.5 **Деталка колоды.** Три кнопки режимов; карточки уровней показывают звёзды
  лучшего прогона; активный прогон: «Прогон L1: 34/120 · Продолжить /
  Сбросить». Замок L2: «Откроется после полного прохождения колоды на
  Уровне 1».

  L1/Просмотр. Бэкенд готов (`direction`, `card_directions`).
2.4 Дневная цель + единый серверный стрик: кольцо прогресса на главной,
  цель из настроек; выпилить `mc_streak` из localStorage.

## Фаза 3 — импорт

3.1 **apkg**: zip+sqlite (legacy `collection.anki2/21`; для `anki21b` —
  сообщение «экспортируйте в legacy-формате», зависимость zstandard не
  добавляем на старте). Поля → strip HTML; первые два поля = front/back,
  остальные → hint; cloze `{{c1::…}}` → карточка «текст с ___» / скрытое
  значение; медиа пропускаются (решение: никакого импорта чужих файлов).
  Через существующий предпросмотр analyze_import.
3.2 **docx**: python-docx → таблицы как tab-формат (кол.1=вопрос,
  кол.2=ответ), абзацы → авто-парсер. Известные потери (формулы OMML,
  картинки) видны в предпросмотре. PDF не делаем.
