## Стратегия

### Принцип: Coverage ROI

Приоритет отдаётся тестам, которые покрывают максимум строк при минимальных усилиях:
1. **Сервисы с чистым API** (вход → выход, без side-effects) — наибольший ROI.
2. **Парсеры и валидаторы** — детерминированная логика, легко тестируется.
3. **Бизнес-логика с состоянием** (сессии, прогресс) — средний ROI, требует fixtures.
4. **HTTP-маршруты** (server.py) — самый низкий ROI до рефакторинга; тестировать через integration после выноса в Blueprints.

### Этап 1: 10% → 25%

**Фокус:** убедиться, что существующие 160+ тест-файлов реально проходят в CI.

1. Прогнать `pytest` локально, зафиксировать текущий % покрытия.
2. Исправить все failing/skipped тесты, которые могут быть включены.
3. Поднять порог до 25%.

### Этап 2: 25% → 40%

**Фокус:** покрытие крупнейших сервисов unit-тестами.

Приоритетные модули:
- `storage_service.py` — CRUD-операции, легко мокать файловую систему
- `statistics_service.py` — вычислительная логика, чистые функции
- `progress_service.py` — агрегация данных
- `difficulty_manager.py` — конфигурация + логика уровней
- `theory_service.py` — CRUD теории
- `user_service.py` — управление пользователями
- `event_bus.py` — pub/sub, уже маленький

Для каждого сервиса:
1. Тест на happy path основных публичных методов.
2. Тест на edge cases (пустой ввод, несуществующий ID, невалидные данные).

### Этап 3: 40% → 55%

**Фокус:** покрытие сложной бизнес-логики.

- `task_evaluator_service.py` — тесты на каждый тип задания (click, draw, test, open_answer, sequence_assembly, error_detection).
- `adaptive_session_manager.py` — тесты на логику повторов, daily_mix, завершение сессии.
- `microcards_service.py` — CRUD карточек, генерация pair_match, аналитика.
- `complex_import_export_service.py` — round-trip export→import.

### Этап 4: 55% → 70%

**Фокус:** интеграционные тесты и server.py.

- После рефакторинга server.py (см. `server_refactoring_plan.md`) — integration-тесты на каждый Blueprint через Flask test client.
- `ai_generation_service.py` — мок внешнего API, тест prompt-строения и парсинга ответов.
- `analysis_schema_v2.py` — валидация схем, нормализация.

## Инструменты

- **pytest-cov** — уже настроен, отчёт в `coverage.xml`.
- **CI gate** — порог поднимается после каждого этапа в `pyproject.toml` (`--cov-fail-under`).
- **Просмотр отчёта:** `pytest --cov-report=html` → `htmlcov/index.html` для визуального анализа непокрытых строк.

## Правила

1. **Никогда не понижать порог** — только повышать или оставлять.
2. **Не писать тесты ради покрытия** — каждый тест должен проверять осмысленное поведение.
3. **Mocking вместо реальных файлов** — использовать `tmp_path` fixture и `unittest.mock` для изоляции.
4. **Тесты не должны зависеть от порядка** — `pytest-randomly` рекомендуется.
